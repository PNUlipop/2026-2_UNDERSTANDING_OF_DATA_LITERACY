# 결정 기록

## 2026-10-16 — 일반 과제 HTML 제작

- 일반 과제 OTT와 기말 뉴스 과제는 별도 디렉터리로 유지.
- 제출물은 13장 단일 HTML. 편집 소스와 데이터·재생성 코드는 별도 보관.
- 사용자 요청에 따라 BMW M 디자인과 Manim·Seaborn·Anime.js 사용.
- Chrome의 로그인된 Google Flow에서 OTT 이미지 생성·다운로드 후 표지와 결론에 적용.
- 보고서에는 선택 이유의 직접 순위 문항이 없어 제목은 유지하되 ‘서비스 평가를 통한 선택 배경 탐색’이라는 해석 범위를 처음과 결론에 명시.
- 전체 플랫폼의 월간 이용 맥락에 유튜브·틱톡을 포함하되, 유료 서비스 상세 비교는 넷플릭스·쿠팡플레이·티빙·웨이브로 한정. 전체 시장 순위와 상세 비교 대상의 범위를 구분.
- 원문 표/본문 집계값을 사용. 개인 원자료 분석이나 유의성 검정으로 표현하지 않음.
- 현재 요청 범위는 로컬 과제 제작. 새 일반 과제의 GitHub 업로드는 하지 않음.

## 4페이지 수동 모션 진행

자동 재생을 제거했습니다. 월간 이용률을 보여주며 대기하고, 첫 다음 입력(Space·오른쪽 방향키·PageDown·다음 버튼·왼쪽 스와이프)으로 비교 모션을 시작합니다. 시작 전 도입 지연을 건너뛰며 재생 중에는 다음 입력을 무시합니다. 완료 후 다시 누르면 다음 장으로 넘어갑니다. 다시 진입하면 대기하며 R로 즉시 재생할 수 있습니다. 모션 꺼짐 상태에서는 정적 차트를 보고 정상 이동합니다.

- 4페이지 화면의 Space/방향키 안내 버튼·재생 상태 문구를 제거. 키보드로 모션 시작 → 재생 중 넘김 방지 → 종료 후 이동 동작은 유지.

- 4페이지의 뒤로 진행을 단계별로 변경. 재생 중 또는 종료 후 뒤로 입력은 같은 페이지의 모션 이전 상태로 복원하고, 대기 상태에서 다시 뒤로 입력하면 3페이지 이동. 왼쪽 방향키·PageUp·이전 버튼·오른쪽 스와이프에 동일 적용. 키를 길게 눌러 복원 직후 3페이지로 넘어가지 않도록 반복 입력 제외.

- 재생 중 넘김 방지를 해제. 4페이지 대기 상태의 첫 다음 입력은 모션 시작, 재생 중·종료 후 다음 입력은 즉시 5페이지로 이동. 이전 상태 복원 동작과 길게 누른 키 반복 방지는 유지.

- 표지·참고자료 과제명: 데이터리터러시의이해 과제1. AI 고지를 페이지 번호 위로 이동.
- 8페이지는 문항별 애니메이션 막대 그래프를 기본으로 하고 Seaborn 히트맵을 보조 보기로 제공. 수치·분모·문항 의미는 동일하게 유지.
- 완결된 설명 문장에 마침표를 사용하고 5·10·12페이지는 사용자 지정 줄바꿈을 적용.

- 8페이지 후속 개선: 반복 플랫폼명과 굵은 막대를 제거하고, 플랫폼 4행 × 평가 문항 4열의 도트 플롯으로 변경. 공통 0–100% 척도, 우측 정렬 수치, 문항별 최고값의 파란 점 강조를 적용. 점은 각 척도의 시작에서 해당 값까지 이동하며 Seaborn 보기는 유지.
